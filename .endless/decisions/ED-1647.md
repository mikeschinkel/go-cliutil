A command declares either one positional argument or one variadic positional argument that takes every remaining value, never two or more distinct positionals. When a command needs several values of different kinds, the extra values are flags. Mike set this on 2026-11-01 in gomion E-2534 as an invariant of go-cliutil, with the reason that multiple positionals make command evolution very difficult: adding, reordering or removing a positional silently changes what every existing caller means, while flags are named and order-free. He gave the shape 'task plan approve <task_id> <plan_item_no...>' as the pattern to avoid and 'task plan approve <task_id> --items <plan_item_no...>' as the shape he wants. Backward compatibility is not a concern: go-cliutil is pre-1.0. Alternative rejected: allowing a scalar positional followed by a variadic tail, as git and rm do; Mike prefers the stricter rule.
