RegisterCommand takes a CommandFunc (a constructor, never called a factory) from the command's own file in init(), keeping the plug-in-by-file model. Each run calls the constructors, so flag and operand targets are fields of a fresh command value and no value leaks between runs. The registry is a Registry type; DefaultRegistry() holds init() registrations; a CmdRunner takes a registry in CmdRunnerArgs, so there is no SetRegistry. Mike chose this in go-cliutil E-2544 on 2026-11-17. Alternatives rejected: registering instances with package-level targets that go-cliutil resets; swapping a global registry with GetRegistry/SetRegistry.
