Mike's rule for registries: code in init() only adds entries and cannot fail. Anything that can fail goes in a public Initialize() error reached from main(), so the CLI exits with a readable message. RegisterCommand broke this in commit 442b786 (flagsets, Nov 2025). It began returning error because of the FlagName-vs-global-flag conflict check and the AddCLIOption call. So callers such as gomion do 'if err != nil { panic(err) }' inside init(). The conflict check is also order-dependent: it only sees global flags already registered. The fix: RegisterCommand only appends (and records parents). The FlagName conflict check and the auto-registration of the flag as a global CLIOption move into Initialize, before BuildCommandTree. Every caller drops its error check: gomion, xmlui-cli, go-stash, doctool, homelab, macmail-ext and others (grep for 'cliutil.RegisterCommand('). Mike has accepted that this may wait a while.
