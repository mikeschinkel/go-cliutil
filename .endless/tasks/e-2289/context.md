The rule for registries: code in init() only adds entries and cannot fail. Anything that can fail belongs in a public Initialize() error reached from main(), so the CLI exits with a readable message. RegisterCommand broke this in commit 442b786 (flagsets, Nov 2025): it returns error because of the FlagName-vs-global-flag conflict check and the AddCLIOption call, so callers end up doing 'if err != nil { panic(err) }' inside init(). The conflict check is also order-dependent, because it only sees global flags registered before it. The fix: RegisterCommand only appends (and records parents); the conflict check and auto-registering the flag as a global CLIOption move into Initialize, before BuildCommandTree. Downstream callers must drop their error checks; those fixes are tracked as tasks in their own projects.
