Found in gomion E-2534 on 2026-11-01. CmdRunnerArgs.Args is os.Args[1:], command words and flags included, and the field has no doc comment; a gomion handler read it as its own positionals and treated repo, setup and --check as directories. CmdBase.AssignArgs copies positional i into ArgDefs[i].String and discards the slice: no handler can see a variadic tail, a positional beyond the declared ArgDefs is silently dropped rather than rejected, and ArgDef.Default is never applied (only FlagDef.Default is, in flag_set.go). Mike's view: Args in the POSIX sense includes flags, so the handler wants three things with narrow names, something like the raw vector (only help needs it), the parameters after the command words, and the positionals alone, with flags already typed through FlagDef pointers. Variadic positionals (ROADMAP item 1) fall out of a positionals slice. Mike also wants flags accepted in any position, as Python's click allows, which he believes go-cliutil does not do today. Backward compatibility is not a concern: go-cliutil is pre-1.0 and Mike calls its architecture best effort at the time. Each gomion command should also get a seam test through CmdRunner, which wants a test helper in go-cliutil so consumers write the table, not the harness.
